# 顧客情報と30分値データの連携（BLMMVMVBUILDING）

`docs/バッチ設計書_顧客情報と30分値データの連携機能バッチ.xlsx` の更新仕様No.1～6と、
`docs/STEP4_テーブル一覧・定義書・ER図.xlsx` の物理名・型を使用しています。

## 実行

依存ライブラリをインストールし、`DATABASE_URL` を設定したうえで、
`cndx_corp_batch` の親フォルダーから実行します。

```powershell
python -m cndx_corp_batch.entrypoints.link_customer_30min
python -m cndx_corp_batch.entrypoints.link_customer_30min --batch-date 2026-05-19 --batch-size 1000
```

実行日を省略すると日本時間の当日を使用します。1～18日は3か月前、19日以降は2か月前が対象です。
既存のPDF作成バッチの切替日設定とは独立しています。取得件数は既定で1,000件です。
作成者・更新者には実行OSユーザーを設定します。

取込バッチからは、取込処理のコミット後に、既存の `BatchContext` を渡して呼び出せます。
このリポジトリには呼出元の30分値・顧客情報取込バッチ（BLMMRTDV）がないため、
その呼出元への組み込みは含みません。

```python
from cndx_corp_batch.domains.link_customer_30min.jobs.link_customer_30min_job import (
    LinkCustomer30MinJob,
)

LinkCustomer30MinJob(context, batch_date=batch_date).run()
```

## 処理と再実行

- 取込状態が「3：完了」、対象年月が一致、紐付け日時が未設定で、有効な建物マスタがある管理行を取得します。
- 建物・企業基本情報・ARVE・対象月のEP30分値を結合し、48時間帯の値と欠測・不正値件数を数値型へ変換します。
- 生データの複合主キーが一致する場合は上書きします。作成者・作成日時は保持し、更新者・更新日時を設定します。
- 取得分ごとに管理行をロックし、生データの登録と管理行の紐付け完了を同じトランザクションで確定します。
- 例外時は取得分全体をロールバックし、その取得分の管理行へ最大100文字のエラーを別トランザクションで記録して停止します。確定済みの取得分は保持します。単独実行の終了コードは正常時0、例外時1です。
- 結合先が不足して登録できなかった供給地点は未紐付けのまま残し、警告を記録します。同じ実行内では再取得せず、次回実行で再度対象にします。
- 紐付け済みの行は再実行時に対象外となります。再連携が必要な場合は、呼出元で該当年月の紐付け日時を未設定に戻す必要があります。

## 設計書の記載差異の扱い

- 更新仕様No.5・6の更新条件に対象年月を追加し、同じ供給地点の別月を更新しないようにしています。
- 日時型の空欄（初回の更新日時・ファイル更新日時）は空文字ではなく `NULL` とします。
- UPSERT例の `EXCLUDED` 参照は登録先の物理列名に合わせています。ARVEお客さま番号はARVEの元番号から分割し、建物マスタのEPお客さま番号とは区別しています。
- テーブル定義の項目一覧には `UPDATED_AT` がありますが、生データのDDL例では抜けています。実装は項目一覧に従うため、実DBにもこの列が必要です。
- 取込管理の主キーは項目一覧では供給地点と対象年月、DDL例では供給地点のみとなっています。実装は両方を更新条件に使います。

## テスト

```powershell
python -m pytest cndx_corp_batch/test/test_link_customer_30min.py -q
```

テストではSQLiteに最小限の関連テーブルを作り、実SQLの結合・登録・上書き、
対象月の境界、再実行、ページ分割、ロールバック、エラー記録、終了コードを検証します。
SQLiteで扱えない行ロック句だけをテスト側で除外しています。
PostgreSQL固有の行ロック動作と不正文字列のCASTエラーは、実PostgreSQLでの確認が必要です。
